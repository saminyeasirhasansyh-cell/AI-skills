# DOTMET — Persona Quality Check (Pearl & Intriligator)

Source: Pearl & Intriligator, *Persona Multiplication: A Method to Avoid Designed Injustice*, Table 1. DOTMET names six ways personas go wrong. Use it to audit any persona set, and to build or select a final set (e.g., "find 5 personas") that passes all six.

"Persona is destiny": personas set the trajectory for research, requirements, testing and marketing. A weak set launches the whole project down the wrong path.

## The six tests

| Letter | Failure → Goal | Definition | Test question | Example error |
|---|---|---|---|---|
| **D** | Static → **Dynamic** | Static personas describe one slice of time, place, situation. Dynamic personas show how the person changes across space, time and situation. | How does this person change across morning/evening, good/bad day, home/away? | Travel app that ignores how a traveler changes in known vs unknown cities |
| **O** | Closed → **Open** | Meta-issue about the team: "persona fascists" design to too few personas, stay myopically in scope, stop looking for change, stymie innovation. | Who did we leave out, and when do we reopen the set? | Designing only to the original persona while users change |
| **T** | Shallow → **Thick** | Thick personas explain the psychological and social motivations under behaviors. | Do we know *why* they do what they do? | Toothbrushing campaign for a community that can't afford toothbrushes |
| **M** | Myopic → **Multiperspective** | One designer's view vs open, multivocal, multidisciplinary sources. | Whose eyes is this persona seen through; whose are missing? | Education designed by and for a narrow student type |
| **E** | Narrow → **Expansive** | Covers a wide range of relevant dimensions and situations. | Which dimensions does the set cover; which are blank? | Safety sign in tiny text, no braille or audio |
| **T** | Outdated → **Timely** | Recognizes changing realities; personas are updated, split (fractionated) or merged (fused). | What is true of this person in 2–5 years? When do we update? | Blockbuster designing for yesterday's customer |

## Procedure

1. Gather candidate personas (e.g., from Persona Multiplication).
2. Audit each against DOTMET: ✔ / ⚠ / ✘ with one line of reason.
3. Fuse personas that are the same person in different slices; fractionate personas hiding two needs.
4. Select the final set so that, as a set, it is Expansive and Multiperspective, and each persona is Thick, Dynamic and Timely.
5. State the Open line: who is knowingly left out, the consequence, and the trigger/date to reopen.
6. Run the PM Stage 2 complication matrix on the final set: personas × scenarios (hear about → obtain → set up → use → outcome).

## Persona card template

```
**[Name], [age] — [one-line identity]** (fuses: …; sources: …)
- Thick (why): behavior + motivation underneath
- Dynamic (how they change): time of day / health / place
- Expansive (dimensions carried): …
- Timely (2–5 yrs): trajectory; update trigger
- Multiperspective (seen by): participant / staff / family / data; missing voice
- Design must: 1–2 requirements
```

## PM Stage 1 heuristics

Invest more in personas when the system is more complex, serves more types of users, carries serious consequences (finance, health, housing), must last (include personas that don't exist yet), or depends on users' physical traits.
